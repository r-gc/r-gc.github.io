零信任系统是一个偏安全架构和答辩演示的项目。它把用户、资源、访问策略、审计日志、安全监控和 SDN 控制器演示串在一起，用 Docker Compose 组织成本地可运行环境。

## 系统结构

从代码结构看，项目主要包含：

- `backend`：Flask 后端服务
- `frontend`：Vue 3 + Element Plus 前端
- `database`：MySQL 初始化脚本
- `sdn_controller`：模拟 Floodlight REST API 的 SDN 控制器
- `tests`：接口级验收测试
- `docker-compose.yml`：数据库、后端、前端和 SDN 控制器编排

本地启动后，前端、后端、数据库和 SDN 控制器分别运行在独立容器中，适合作为毕业设计或答辩环境演示。

## 后端模块

后端使用 Flask 注册了这些 API 模块：

- `/api/auth`：登录、登出、token 校验
- `/api/users`：用户管理
- `/api/access`：资源访问检查
- `/api/policies`：访问策略配置
- `/api/audit`：访问日志、登录日志、安全事件
- `/api/monitor`：安全监控、拓扑、流量、控制器状态

数据模型也围绕零信任访问控制展开：

- 用户
- 资源
- 策略
- 访问日志
- 登录日志
- SDN 规则
- 安全事件

其中访问检查会记录访问日志，这对“零信任不是只做认证，而是持续审计”的叙事比较有帮助。

## 前端页面

前端使用 Vue 3、Vue Router、Pinia、Element Plus 和 Chart.js。

路由结构包括：

- 登录页
- 系统仪表盘
- 用户管理
- 资源管理
- 策略配置
- 日志审计
- 安全监控

部分页面带有管理员权限限制，普通用户访问管理功能会被路由守卫拦回仪表盘。

## SDN 控制器演示

项目里的 `sdn_controller` 是一个模拟 Floodlight REST API 的服务。它初始化了交换机、端口、链路和主机信息，并提供控制器摘要、交换机列表、拓扑链路、设备信息和静态流表下发接口。

这让系统可以在没有真实 SDN 环境的情况下，演示“策略配置 -> SDN 规则 -> 流表下发”的闭环。

从演示角度看，这是一个很实用的取舍：项目能讲清楚架构和链路，也能在答辩环境稳定运行。

## 验收测试

项目提供了接口级验收测试，覆盖范围包括：

- 后端和 SDN 控制器健康检查
- 错误登录、管理员登录、普通用户登录、token 校验
- 普通用户访问管理员接口的 403 权限控制
- 用户管理、资源管理、策略配置
- SDN 控制器状态、交换机列表、流表新增、部署和撤销
- 访问日志、登录日志、安全事件和统计趋势
- 安全监控、拓扑、流量和实时指标

这些测试不是浏览器点击测试，而是 HTTP/API 级别验收。它更适合在答辩前快速确认核心链路是否可用。

## 项目价值

这个项目的价值不只在于实现了几个 CRUD 页面，而在于把零信任相关的几个关键概念组织到一个可运行系统里：

- 身份认证
- 资源建模
- 策略决策
- 访问审计
- 安全监控
- SDN 策略下发

它适合作为安全方向项目展示，也适合继续扩展成更完整的访问控制平台。
